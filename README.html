1. Руководство пользователя

Что это

Сервис принимает JSON-запрос с перечнем регионов, которые посетил пользователь, и возвращает PNG-картинку с закраской этих регионов по федеральным округам. На карте отображаются границы регионов, основные реки, озёра (Байкал, Ладога, Онега) и Азовское море.

Базовый URL и эндпоинт

Базовый URL: https://maps-russia-service.onrender.com

Эндпоинт: POST /map

Заголовок: Content-Type: application/json

Формат запроса (JSON)

{
  "client_id": "user_123",
  "first_name": "Иван",
  "last_name": "Петров",
  "regions": [
    {
      "region_name_en": "Moscow",
      "district_name": "Центральный"
    },
    {
      "region_name_en": "Saint Petersburg",
      "district_name": "Северо-Западный"
    }
  ]
}
ПолеТипОбязательноеОписание
client_idстрока✅Уникальный идентификатор пользователя
first_nameстрока✅Имя пользователя
last_nameстрока✅Фамилия пользователя
regionsмассив✅Список посещённых регионов
regions[].region_name_enстрока✅Английское название региона (точное совпадение с данными Natural Earth)
regions[].district_nameстрока✅Название федерального округа (определяет цвет заливки)

Допустимые значения district_name:

  • Дальневосточный
  • Приволжский
  • Северо-Западный
  • Северо-Кавказский
  • Сибирский
  • Уральский
  • Центральный
  • Южный

Ответ и ошибки

  • 200 OK – возвращает изображение PNG с Content-Type: image/png.
  • 400 Bad Request – ошибка в JSON (неверный формат, отсутствие обязательных полей).
  • 500 Internal Server Error – внутренняя ошибка (свяжитесь с разработчиком).

Пример cURL

curl -X POST https://maps-russia-service.onrender.com/map \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "user_123",
    "first_name": "Иван",
    "last_name": "Петров",
    "regions": [
      {"region_name_en": "Moscow", "district_name": "Центральный"},
      {"region_name_en": "Saint Petersburg", "district_name": "Северо-Западный"}
    ]
  }' \
  --output map.png
Примечание: Если регион не найден в данных, он игнорируется (не закрашивается).

2. Руководство разработчика

Архитектура и стек

  • Язык: R (≥ 4.6.1)
  • Веб-фреймворк: plumber
  • Пространственные данные: sf, rnaturalearth, rnaturalearthhires
  • Визуализация: ggplot2
  • Деплой: Docker + Render

Структура репозитория

MAPS_RUSSIA_1.0/
├── Dockerfile
├── .dockerignore
├── data/
│   ├── input/                 # тестовые JSON
│   └── rds/                   # RDS‑файлы с пространственными данными
│       ├── combined.rds       # полигоны регионов (Россия + выбранные области Украины)
│       ├── russian_rivers.rds # линии крупных рек
│       ├── selected_lakes.rds # полигоны озёр (Байкал, Ладога, Онега)
│       └── azov_sea.rds       # полигон Азовского моря (опционально)
├── scripts/
│   ├── generate_from_json.R   # основной скрипт генерации карты по JSON
│   ├── api.R                  # Plumber‑сервер
│   ├── export_user_json.R     # экспорт данных из БД в JSON
│   └── setup.R                # первичная настройка (создание RDS)
├── output/                    # выходные PNG (локально)
└── README.md

Как это работает (по шагам)

  1. Запрос: клиент отправляет POST‑запрос с JSON‑телом на /map.
  2. Валидация: api.R проверяет наличие обязательных полей.
  3. Загрузка данных: load_data() загружает RDS‑файлы.
  4. Обработка регионов: для каждого региона из regions ищется полигон в combined по полю name_en. Добавляется колонка district_visited.
  5. Построение карты: ggplot2 создаёт слои:
    • заливка регионов (цвета по округам, непосещённые – светло‑серые #E8E8E8)
    • реки (синие линии)
    • контуры регионов (тёмно‑синие)
    • озёра и море (голубые полигоны)
  6. Сохранение PNG: график сохраняется во временный файл, читается как raw и возвращается клиенту с Content-Type: image/png.

Деплой на Render

  • Сборка Docker‑образа по Dockerfile на базе rocker/geospatial.
  • Переменные окружения не требуются.
  • Порт 8000 открыт.

Как добавить новый водный объект или реку

  1. Найдите или создайте полигон/линию в формате sf.
  2. Сохраните как RDS в data/rds/.
  3. Добавьте в load_data() и в слой ggplot в обоих файлах (generate_from_json.R и api.R).
  4. Пересоберите и задеплойте.
Важно: При добавлении нового файла убедитесь, что он не исключён в .dockerignore и присутствует в репозитории.

3. Руководство для ИИ-инструментов

Цель

Документ описывает архитектуру и ключевые точки расширения сервиса, чтобы ИИ-ассистенты могли предлагать улучшения, исправлять баги и добавлять новый функционал.

Архитектура (схема)

Клиент → (JSON) → [Plumber API: /map] → (загрузка RDS) → (обработка) → (ggplot) → PNG → Клиент

Ключевые файлы

ФайлНазначениеЧто можно улучшить
scripts/api.RPlumber‑сервер, приём запросовЛогирование, авторизация, кеширование
scripts/generate_from_json.RЛогика построения картыОптимизация, новые слои
scripts/export_user_json.RЭкспорт из БДПоддержка других источников
data/rds/combined.rdsПолигоны регионовЗамена на более точные данные (GADM, OSM)
DockerfileСборка образаОптимизация размера

Возможные направления улучшения

  • Производительность: уменьшить время загрузки RDS (использовать qs или fst), кешировать результаты.
  • Расширение данных: добавить города, метки, поддержку русских названий регионов.
  • Кастомизация: параметры запроса: width, height, format, цвета.
  • Безопасность: API‑ключ, ограничение запросов, логирование ошибок.
  • Интеграция: поддержка GraphQL, веб‑сокеты.

Примеры запросов к ИИ

  • "Как добавить поддержку русского названия региона в JSON?" → добавить словарь перевода в generate_from_json.R и расширить логику поиска по region_name_ru.
  • "Как ускорить сборку Docker‑образа?" → использовать многоступенчатую сборку, кешировать установку пакетов.
  • "Как добавить новый источник данных для полигонов?" → заменить combined.rds на данные из GADM или OSM, обновить load_data().
Совет: При обнаружении ошибки или идеи улучшения создавайте Issue в репозитории или предлагайте pull request.
